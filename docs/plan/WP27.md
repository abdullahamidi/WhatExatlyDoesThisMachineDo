## Goal
Make the click matter for the whole game without making it mandatory:
- era I is hand-led: Worn Motor is a small helper (+2 ME/s, 0.67 click/s), not a 17-click/s jump;
- the mechanical click grows with the machine and is never worth less than any other energy's click (D2);
- two new active mechanics keep clicking warm late: **Machine Faults** (a part of the machine faults now and then; clear it for a
  burst of output) and the **Wind-up** click branch (the machine stores output; the next manual turn of the crank releases it);
- the era I crow sits, pecks and looks around (no frozen spread-wing picture); Sensor 7 stays next to the Inspector in era II.

## Director decisions (binding; copied from the dispatch)
- **D1 Three-phase curve.** Profile A = the active greedy profile at 4 cps with buys every 1 s; in WP27 it also clears every fault
  2 s after it appears.
  - "Hand" (0 to ~4 min): Worn Motor is worth 0.5-1 click/s when bought; A's ME click share is ≥ 75 % until 2:00 and ≥ 50 % until
    4:00; ME passive passes A's 4-cps clicking between 4:00 and 8:00 (around Piston Array).
  - "Hand + machine" (rest of era I through era II): A gets 30-50 % of frontier income from clicks; one click is worth ≥ 0.5 s of
    output in every energy that has passive.
  - "Machine" (eras III-V): plain clicks ~10-25 %; with the click branch (D4) and Faults (D3) an active player earns ≥ 35 % from
    active play.
  - Whole run: W5 (4 cps for 5 min, then 0.5 cps, no faults) finishes at 1.2-1.6 × A. A's PF within ±10 % of today; demo A
    substation within ±15 %; every existing era-window, dead-time and "all energies stay useful" gate holds or is re-targeted with
    a reason.
- **D2 ME click parity.** From the first Gear Ratio level on, at every sample of A's run, `perClick.me / perSecond.me ≥
  perClick.r / perSecond.r` for ee, pr, rs and xf whenever both are > 0. Early ME click upgrades are the strongest click upgrades.
- **D3 Machine Faults** ("FAULT"). A visible part of the current machine faults for a short window. Clicking it (or a key) clears
  it and pays N seconds of the current output of every energy with perSecond > 0 (never zero ME). Missing one costs nothing.
  - Unlock: an era I node, so the demo has it. Spawn only while the game is visible and interactive; seeded RNG interval; never in
    the first 3 min; never offline; never more than one alive.
  - Eras II-V nodes raise payout / frequency / window; one late node adds a short Overdrive.
  - Save: additive v2 fields only, no version bump. A11y: key, screen-reader line, reduced motion = steady marker, colour + shape.
  - Art by the AD within ART_BRIEF (≤ 3 Hz flicker). Audio: short synth cues, data in `src/data/audio.ts`. Text: the machine's dry
    voice; one system line at unlock; no spoilers.
- **D4 Click branch.** 3-5 nodes over eras II-V; a fully invested era V click is worth ≥ 2 s of output in every energy. Slots fit
  the layout; the WP26 no-crossing guard stays green; the demo shows era I-II nodes only.
- **D5 Crow.** Base state perched with folded wings and varied actions; the spread-wing pose only as a rare glitch ≤ 2 s; era II
  the same; the AD draws missing perched frames; the crow's V4 max-gap gate becomes 20 s.
- **D6 Era II device.** The AD confirms it is Sensor 7; it stays next to the Inspector in every framing that shows the Inspector;
  audit eras I-II for other missing objects; unit test "every framing that places the Inspector also places Sensor 7".
- **D7 Feedback.** The HUD click-worth readout stays; click popups show ME and echo values; a fault clear shows its payout; the tree
  describes the new effects in plain words.
- **D8** Version 0.11.0; CHANGELOG; GAME_SPEC; STORY_BIBLE; PROJECT_STATUS; the Director runs STEAM_RELEASE §15 after the package.
- **D9 Budgets.** GPU p95 ≤ 17 ms; world update budgets; display objects ≤ 100. The app limit may go to 510 KB only if the plan

## Machine Faults design (D3)

### State machine (pure, `src/simulation/faults.ts`; one clock per run)
```
LOCKED    --(eligible step, dt > 0: eligibleSeconds += dt; nothing else)--> LOCKED                                   [R1]
LOCKED    --(faultLamp owned)--> ARMING
ARMING    --(first eligible unlocked step: eligibleSeconds += dt; nextIn = max(draw(), firstAfterS - eligibleSeconds))--> WAITING
WAITING   --(eligible steps: eligibleSeconds += dt; nextIn -= dt; nextIn <= 0)--> ALIVE { age 0, window, serial }  event spawn
ALIVE     --(clearFault: payout, overdriveLeft = overdriveSeconds, nextIn = draw())--> WAITING                    event clear
ALIVE     --(eligible steps: eligibleSeconds += dt; age += dt; age >= window: nextIn = draw())--> WAITING            event expire
any state --(not eligible, or dt not a finite number > 0)--> unchanged: the same object                            [R1]
draw() = (intervalS[0] + (intervalS[1] - intervalS[0]) * u) * intervalFactor   // u = one mulberry32 step of the clock rng
```
- At most one fault is alive (structural: WAITING is the only state that can spawn).
- **[R1]** The pure step never clamps (the greedy passes 1 s steps and must equal h27). `GameSession.stepFaults` clamps `dt` to
  `FAULTS.maxStepS` (0.25 s, data) before the step, so one long frame can neither age a fault out nor skip the countdown
  (`MAX_UPDATE_SECONDS` is the 8 h offline cap: useless as a frame clamp).
- **[R1]** `eligibleSeconds` counts every eligible second since the clock was created (run start, page load, new cycle, reset),
  locked or not; "locked" only skips arming and spawning. The first fault therefore comes `max(draw, 180 − eligibleSeconds)` after
  the arming step: 90-180 s after Fault Lamp in a long session (A: bought at step 421, armed at 422, spawned at 549), and never in
  the first 3 min of a run or of a session.
- Never offline: the clock moves only through `stepFaults`, which the World scene calls per frame; `applyOffline` never touches it.
- Overdrive: `overdriveLeft` counts down in `GameSession.update` (active time); a clear refreshes it and never stacks it.

### Payout
`payout[r] = perSecond[r] > 0 ? payoutSeconds × perSecond[r] : 0`, with `perSecond` = `session.rates.perSecond` (servo included,
Overdrive not included) and `payoutSeconds = Σ faultUnlock.seconds × L + Σ faultSeconds.seconds × L` (15 / 18 / 22 s). ME is never
0 once faults are unlocked (Worn Motor is a prerequisite). Overdrive: while `overdriveLeft > 0`, `update` credits
`advance(state, dt + (overdriveFactor - 1) × min(dt, overdriveLeft))`.

### Eligibility ("visible and interactive"): pure `faultEligible(gates)` in `src/game/math/faultMarker.ts`
Eligible only when ALL hold: tab visible; no photo mode; TECH INDEX closed; no era card; no modal (system menu, credits, cycle
confirm, demo end card, reset confirm); no cycle transition; teaser off; `ending.phase === 'none'` (no finale, choice or
postgame); faults enabled (debug `setFaults`); at least one anchor of the current era on screen. While not eligible the clock is
frozen, the marker is hidden and the key does nothing.

## Wind-up design (the click branch, D4)
- Capacity and refill: `cap = Σ windup.seconds × L` and `refill = Σ windup.refill × L` over owned techs (0.35 s at Reinforced
  Crank; 2.0 s and 0.2 s/s fully invested).
- Stored seconds live in the session (not saved, P5): `+ refill × dt` in `update` and `+ refill × cappedSeconds` in
  `applyOffline`, clamped to `[0, cap]`.
- A manual click releases ALL of it: `gained[r] = stored × perSecond[r]` for every energy (servo included); then stored = 0. Servo
  auto-cranks never release it. A 4-cps player gets about `refill × output` extra; a player who clicks once every 10 s gets a 2 s
  burst per click (the rested click).
- Feedback: HUD row `WIND-UP 1.4/2s` (title: "Stored machine output. The next turn of the crank releases it."); a release of at
  least 0.05 s puts the line `RELEASE +1.4s` first in that click's gain block.

### C2 Formula (`src/simulation/production/rates.ts`)
```
E = Σ crankEcho.seconds x L
perSecondPre[r] = today's formula
perClick.me     = clickAdd x clickMult + E x perSecondPre.me          // the E part is NOT multiplied by clickMult
perClick[r]     = (echo[r] + E) x perSecondPre[r]                     // r != me
perSecond[r]    = perSecondPre[r] + autoClicks x perClick[r]          // servo fold-in, ME echo included
```
Property (unit-tested, any levels): `perClick.me / perSecond.me >= perClick.r / perSecond.r` whenever both are > 0. Proof: with
flat part F >= 0 and p = perSecondPre.me, cross-multiplying `(F + E p) / (p + a (F + E p))` against `E / (1 + a E)` leaves `F >= 0`.
The other new effect types contribute nothing in `computeRates` (explicit no-op cases).

### C4 Faults (`src/simulation/faults.ts`, new, pure; data in `src/data/faults.ts`)
```ts
export interface FaultParams { unlocked: boolean; payoutSeconds: number; intervalFactor: number; windowSeconds: number;
  overdriveSeconds: number; overdriveFactor: number }
export function faultParams(levels, techs?): FaultParams;   // windowSeconds = FAULTS.windowS + Σ faultWindow; factor 1 and seconds 0 when absent
export interface FaultAlive { age: number; window: number; serial: number }
export interface FaultClock { rng: number; nextIn: number | null; alive: FaultAlive | null; overdriveLeft: number;
  eligibleSeconds: number; spawned: number; caught: number; missed: number }
export function createFaultClock(seed: number): FaultClock;          // rng = the seed as int32, nextIn null, counters 0
export function nextUnit(rng: number): { u: number; rng: number };   // mulberry32, bit-identical to <O>/eco/h27.ts:172-179
export function stepFaultClock(c: FaultClock, p: FaultParams, dt: number, eligible: boolean): { clock: FaultClock; event: 'spawn' | 'expire' | null };
export function clearFault(c: FaultClock, p: FaultParams, perSecond: Readonly<ResourceMap>): { clock: FaultClock; payout: ResourceMap } | null;
export function consumeOverdrive(c: FaultClock, p: FaultParams, dt: number): { clock: FaultClock; extraSeconds: number };
  // extraSeconds = (overdriveFactor - 1) x min(dt, overdriveLeft)
```
**[R1]** `stepFaultClock` order (h27 parity; replaces the earlier one-line wording):
1. frozen: `!eligible`, or `dt` not a finite number > 0: return the input object, event null;
2. `eligibleSeconds += dt` (locked or not: the clock counts eligible time from its creation);
3. locked (`!p.unlocked`): return (no arming, no spawn);
4. alive: `age += dt`; if `age >= alive.window`: `alive = null`, `missed += 1`, `nextIn = draw()`, event expire; return;
5. `nextIn === null`: arm `nextIn = max(draw(), FAULTS.firstAfterS - eligibleSeconds)`; return (the arming step never spawns);
6. `nextIn -= dt`; if `nextIn <= 0`: `alive = { age: 0, window: p.windowSeconds, serial: spawned }`, `spawned += 1`, `nextIn = 0`,
   event spawn.

`clearFault`: null when none is alive; else the payout, `caught += 1`, `alive = null`, `overdriveLeft = p.overdriveSeconds` when it
is > 0 (refresh, never added), `nextIn = draw()`. `draw()` takes one `nextUnit` step of `rng`; arming, clear and expire take one each,
in the order of h27's spawn rng. Inputs are never mutated. The pure step never clamps `dt` (see the state machine notes).
